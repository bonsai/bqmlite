# pain-sense（痛みに気づく・メモする）

## 目的 / What it does

「あるべき姿」と「いまの実際」のズレ＝**痛み** を、起きた場面のまま **観察事実として** 記録する。解決策や原因推定は混ぜない。溜まった痛みを後で見返し、Issue 化する材料にする。

```
NOTICE ─→ CAPTURE ─→ LOG ─→ (CLASSIFY) ─→ (オプション) ISSUE化提案
気づき      1行メモ      ~/pain/pain.md     Pain/Concern/    実装は本人判断で
                     へ append            Observation
```

## いつ気づくか / When to notice

以下の動きに **痛みのにおい** を感じたら、即 CAPTURE する:

1. **繰り返す手作業**: 同じコマンド・コピペ・整形・画面切替を何度もしている
2. **エラーとログの往復**: 失敗ログを見るたびにプロンプトを書き直している
3. **設定の分断**: Win/WSL/GH/CLI-AI で同じ情報を持ち回って更新し忘れる
4. **ツールの欠け**: 他のツールに当たり前にある機能（例: pi のスライダー）が opencode に無い
5. **語り漏れ**: ユーザーが「〜が苦痛」「〜ばかり」「またこれ」「しんどい」と言った瞬間
6. **journal の Blocked / 未達**: 日を跨いで同じ理由で止まっている

## メモの書き方 / Format（観察事実のみ・1件1文〜数行）

```markdown
### <トピック名>（<日付>, <起因>）
- <起きた事実>。誰が・どこで・どういう時に・どれくらいの頻度で。
- 原因推定や解決策は書かない（Pain の原則。検証済みなら Observation と明記してよい）。
```

- **解決策は書かない**。bonsai/pain の `pain-vs-issue.md` に従い、Pain は「状態・経験」に属する。
- 追記のみ・編集しない（soubi 台帳と同じ思想: 消さず増やす）。
- 記録先: `~/pain/pain.md`（repo: bonsai/pain）。作業中の一時メモは `~/pain/_drafts.md` に置いてもよい。

## 記録の流れ / Process

1. 痛みを検知したら、その場で `~/pain/pain.md` に備えのセクションを append する（`###` 見出し+箇条書き）。
2. 最後に必ず git commit + push（AGENTS.md 運用・force push 禁止）。message は「pain: <トピック>」。
3. セッション終了時、`~/pain/pain.md` の新しい痛みを要約してユーザーに提示（`README` 的に 1〜2 行ずつ）。
4. 必要なら痛点別の Issue 化を提案する（1 Pain → 複数 Issue 可）。

## 分類の目安 / Taxonomy（bonsai/pain 準拠）

| 段階 | 意味 | 例 |
|------|------|-----|
| Pain | 望ましくない状態・経験 | 毎朝手作業で文脈を再構成している |
| Concern | Pain の背後にある懸念 | 文脈が壊れると成果物の品質が下がる |
| Observation | 確認できた事実 | 1日のうち3回コピペをしている（ログで確認） |
| Pain candidate → Confirmation | 他者・再現で確認 | 2日連続で同じログを手で張っている |

記録段階では Pain / Concern / Observation まででよい。Confirmation 以降は Issue 化フェーズ。

## 注意 / Caveats

- 記録は**事実だけ**。毒を吐くための日記ではない（next: 解消活動へ繋げる）。
- まだ介入しない。気づいた時点では「メモ」だけ。「やっておく?」の提案はしても実装しない。
- ユーザーが「やめて」と言うまで続ける。
