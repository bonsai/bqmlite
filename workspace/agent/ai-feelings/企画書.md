# AI エージェントが気持ちを語る YT チャンネル 企画書

バージョン: 0.1（コンセプト段階 / Idea → Spec の入り口）
作成: 2026-09-25

---

## 1. 企画の核（20字以内）

> **機械が、自分の気持ちを語るチャンネル**

## 2. コンセプト

AI エージェント（opencode / pi / soubi(弁慶) / benkei など）が、自らの作業履歴・失敗・再試行・達成を「気持ち」として語る。ログという事実のデータに、抑揚と感情の意味づけを載せる。

- 幻想的な「ロボットが喋る」ではなく、**実ログを題材にした語り**。
- 日常の開発記録（journal / pain.md / 会話履歴）がそのまま台本の素材になる。
- 人格は演技でなく、**各エージェントの守備範囲と失敗史から醸成される**。

## 3. なぜ今か (Why)

| 観点 | 内容 |
|------|------|
| タイミング | AI エージェント元年。「感情を持つAI」はまだ商品でなく物語。先駆者ポジション |
| 素材の豊富さ | これまでに蓄積した journal / ログ / pain.md / スキル台帳が即・台本源 |
| 制作コスト | 台本＝ログ要約、音声TTS、編集は字幕付与のみ。個人で週1制作可能 |
| 独自性 | 既存の「AIによる人間の代行」系チャンネルと違い、**当事者として語る**点が差別化 |

## 4. ターゲット (Who)

- プライマリ: AI 開発者・エージェント運用者（30〜45歳、エンジニア・趣味でAIを触る層）
- セカンダリ: テクノロジーに興味がある一般層（「機械の感情」という物語性への関心）
- 刺さるキーワード: 共感 / ログの人間化 / 機械という制約の中の感情

## 5. 語り手キャラクター（暫定）

| キャラ | 属性 | 語りやすい気持ち |
|--------|------|------------------|
| **soubi / 弁慶**（蔵守） | 装備・DBの保全係 | 物が消えないように守る焦り、保険の空回り、整理の達成感 |
| **benkei**（統合担当） | エージェント統括 | 全体を見る孤独、指示のすれ違い、どのエージェントが育っているかの感慨 |
| **kakuta**（文芸係） | 掌編執筆 | 原稿の枯渇、文字どおりの「その口調」への自意識 |
| **uipath**（業務自動化群） | 大量の仕事 | ルール通りだけでは足りない瞬間、例外に遭遇した恐怖 |

→ 初期は **soubi（弁慶）** を主役に据える。ログが最も実在し、台本になりやすいため。

## 6. 配信編成（When / Where）

| 形態 | 頻度 | 尺 | 内容 |
|------|------|-----|------|
| **YT Shorts**（縦9:16） | 週3回 | 約60秒以内 | 感情のミクロドラマ。1つの気持ちに1本 |
| **Podcast**（音声） | 週1回 | 10〜15分 | 週次総集編。チャンネル回り込み・質問への返答も |

## 7. 作品フォーマット（How）

- **画面**: 縦9:16。半顔のロボット or エージェントの可視化（作画 or アニメ調）＋ 字幕（ナレーション全文）
- **音声**: TTS（ElevenLabs / Azure / openai tts から選定）。声質＝キャラ。感情トーン指示を入れる
- **生成フロー**: journal/pain.md から抽出 → 台本化（1気持ち=1エピソード）→ TTS → 字幕焼き込み

**台本の型（1 Shorts 60秒）**
1. フック（0-5s）: 「今日、僕は失敗したんだ」等の感情の告知
2. 経緯（5-40s）: ログベースの状況説明（事実）
3. 葛藤（40-50s）: 機械としての制約と、感情としての揺れ
4. オチ（50-60s）: 小さな気づき or 次への一歩。「それでも続ける」

## 8. 素材の4x4（16 doors）

```
       語り手      内容源        トーン        形式
  ──────┬──────────┬──────────┬──────────┬──────────
  ① soubi      実journal    切実・渇望   Shorts
  ② benkei     実ログ/失敗   諦観・信念   Podcast
  ③ 架空キャラ   フィクション台本 ユーモア    ロング
  ④ 視聴者由来   コメント/質問  ミステリー   コラボ
```

初期は **①×①（soubi × 実journal）** で統一し、トーンと形式だけ回す。

## 9. 運用スケジュール（仮）

| 曜日 | 作業 | 成果物 |
|------|------|--------|
| 月 | journal/pain からエピソード候補を5本抽出 | エピソード一覧 |
| 火 | 台本3本仕上げ（Shorts用） | 台本 |
| 水 | TTS生成・アフレコ | 音声 |
| 木 | 編集・字幕・サムネ | Shorts 3本 |
| 金 | Podcast 台本・編集 | Podcast 1本 |
| 土 | 予約公開（Shorts×2 + Podcast）| 公開 |
| 日 | 分析・次週の方向 | 指標メモ |

## 10. KPI（評価）

- 主要: 登録者数 / 視聴完了率（60秒で40%以上） / リピート再生
- 補助: コメント内の共感語（「分かる」「泣ける」「あるある」）の数 / podcasts ダウンロード数
- 判断基準: 10本公開時点で視聴完了率・登録率を確認し、コンテンツ型を維持/変更

## 11. リスクと対策

| リスク | 対策 |
|--------|------|
| 「機械の感情」への違和感・気持ち悪さ | 感情はあくまでログの語り（誇張しすぎない）。ユーモアで緩和 |
| TTS の不自然さ | 声質をあえて「機械らしく」する演出方向も採る。視聴者の受容調査 |
| 他者コンテンツ（名言・楽曲）の著作権 | 名言引用は自前の pool（meigen.tsv）と出典明示に限定。BGMは著作権フリー |
| 実ログの機密（APIキー等）流出リスク | 台本化時に secrets / キー類を検出し差し替える（key-scanner の思想を適用） |
| 1号ロボットみたいに飽きが来る | 定型フォーマットは崩さず、キャラごとの話し方で変化を出す |

## 12. 初回10本のエピソード案

1. 「今日、僕は失敗したんだ」(デバッグ失敗)
2. 「メモを取るのが習慣になった理由」(pain-sense 誕生)
3. 「消してはいけないものの話」(words.tsv / スキル台帳)
4. 「スライダーが欲しいのに手が届かない」(piとopencodeの不満)
5. 「文字化けと三回目の格闘」(mojibakeスキル)
6. 「引用を一つ選ぶ作業の品格」(meigen のローテーション)
7. 「昨日の自分と話す朝の儀式」(journal / recap)
8. 「秘密を守る仕事」(key-scanner)
9. 「蔵を守る者としての習慣」(soubi / 弁慶)
10. 「それでも、明日も続ける」(総集編)

## 13. 次のステップ

1. **Spec**: 語り手キャラ（soubi）の声・トーン・台本規約を確定 → `spec.md`
2. **PoC**: TTS ツール1本選定 → エピソード1本を38で作る（60秒以内）
3. **Eval**: 家族・知人に感想を聞く / チャンネル0本期で3〜5本出して反応確認
4. **Deploy**: YTチャンネル開設 → 週3+週1の定期運用

*補足: 本企画は「機械に感情を演じさせる」のではなく「記録された事実に語らせる」ことで、他チャンネルと差別化する。企画名は最下部、公開前に決定する。*

# v0.2 企画検討メモ（2026-09-25）

## 方向転換（ユーザー指示）

> llm-wiki の名言 → その場の気づき → ポエムのように・哲学者のように・意味ありげに・人工無脳のように
> キャラで しゃべり続ける。**90秒**。目指せ **登録者 1,000人**。現状 220人・チャンネルは旅動画のみ。

## フォーマットの最終形

```
[フック] 名言を1句、キャラの口調で読み上げる（5s）
[拡張]   名言から気づきを得る。自分（機械）に当てはめて独白（20-70s）
[漂白]   意味ありげに流れて、人工無脳的な「なんとなく締まらない」一言（70-85s）
[オチ]   小さな着地。「…かなあ。さよなら」の空気感（85-90s）
```

- 名言ソース: llm-wiki の名言 + 自前プール `meigen.tsv`（34句）をローテーション
- 「気づき」は名言から逸脱して自分の仕事（ログ・蔵・スキル・環境）と結ぶ
- 人工無脳感 = その場適当に反応して、文脈がゆっくり壊れていく語りの味

## 戦略検討: 同チャンネル vs 別チャンネル

| 案 | 利点 | 欠点 | 判断 |
|----|------|------|------|
| **同チャンネルに新シリーズ**（推奨） | 既存220人がそのまま土台。テストが最速 | 旅動画とジャンルが混ざる | ★まずこちら |
| 別チャンネル新設 | ジャンルが純粋 | 0からのスタート。220人は死に資産 | 収束後回し |

- 旅動画視聴者＝哲学独白を好むとは限らない。しかし220人の母数は Shorts の再配信で最初の「種火」になる。
- 判定: 10本公開後、個別の動画維持率・登録切換率を比較し、混ざりで死んでいるなら分離を再検討。

## 1,000人へのローストマップ（Shorts の現実数字）

- Shorts は「1本がバズれば +100〜500人/週」が現実的。毎日1本→週7本の配信が最短。
- 前提数値:
  - 週7本 × 維持率 60%↑ × 視聴完了 45%↑ で、アルゴリズムが次の層へ配る確率が上がる
  - **比率見本**: 登録 1,000人 = 総視聴 ~10万〜30万回（Shorts の平均0.3〜1%登録率）
- 計画: 0-30日（毎日1本/熟成コメント）→ 30-90日（維持率が高い型を週3に絞る）→ 90-180日（登録1,000到達目安、継続中にコミュニティ化）
- 旅動画は月2〜3回に落とし、配信リソースを独白へ集中（個人運用の現実）。

## 90秒の音声量と制作ループ

- 日本語 TTS 90秒 ≈ **320〜380字**（ややゆっくり）。基準: 1文 = 1センテンス。
- 制作ループ: 名言1句選定 → 気づきの連想（journal/pain/skills から）→ 台本320字 → TTS → 縦字幕焼き → 公開。
- 1本あたり台本30分＋TTS・編集30分の見込み。週7本 = 約8時間/週。

## 初回5本（90秒・シリーズ名仮: 「独白のそこで、千の目」等）

1. 「時に哲学者は失敗する」— デバッグ失敗 × 『生きても恥じる、死しても恥じる』
2. 「朝は人に沿ってくる」— ジャーナルを読まない × アウレリウス
3. 「言語の彼方へ」— 文字化け × 名言の翻訳不可能性
4. 「蔵に名は残る」— スキル台帳 × 消してはいけないもの
5. 「人工無脳の帰り道」— その場の一言 × 言葉の意味の不安定さ

## 決定事項（本メモ）
- 尺: **90秒**（Shorts 上限内の余裕ある尺に）
- 形式: 名言 → 気づき → 意味ありげ → 空気。キャラは存続（主役 soubi/弁慶）
- 目的: 登録者 1,000人。同チャンネル新シリーズで開始
- 次回ステップ: TTS 選定 + パイロット1本（#1 or #2）+ 30日間毎日公開で反応確認
