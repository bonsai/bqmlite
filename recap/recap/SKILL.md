# Recap（ジャーナル日別要約）

## 目的 / What it does

AI・人間の作業セッション終了時に、そのセッションを **達成 (done) / 未達 (todo) / ブロック (blocked)** に分類して整理し、
**日別マークダウン** として journal に保存する。

- 未来の自分（と別のエージェント）が「あの日あのセッションで何をやったか」を 30 秒で思い出せるようにする。
- gap.md / tasks.md などと違い、**時系列の記録** として付ける。

## 保存先 / Target

```
~/.journal/<YYYY-MM>/recap-<YYYY-MM-DD>.md
```

- ルート: `~/.journal/`（＝ `\\wsl.localhost\Ubuntu\home\bons\.journal\`）
- 月別ディレクトリ: `<YYYY-MM>`（例: `2026-09`）
- ファイル名: `recap-<YYYY-MM-DD>.md`
- 同日のセッションが複数ある場合: **既存ファイルに追記**（`## セッション <HH:MM>` を分けて追記）

## フォーマット / Format

```markdown
# Recap <YYYY-MM-DD>

## セッション <HH:MM>

## 概要
（その日・そのセッションで何をしたか、2〜3行）

## 達成 (Done)
- 完了した成果（ファイル・commit・URL など具体物を添える）

## 未達 (Todo / 未完)
- 着手したが未完・未対応のもの

## ブロック (Blocked)
- 障害・停滞中・待ち条件（無ければ「なし」）

## 次の予定
- （任意）次にやること
```

## 手順 / Steps

1. セッションの履歴（会話・ツール実行・ファイル変更・commit）を確認し、アクションを抽出する。
2. 内容を「達成 / 未達 / ブロック」に分類する。
3. 月ディレクトリが無ければ作成し、日別ファイルへ保存する。既存ファイルがあれば `## セッション <HH:MM>` で追記する（上書きしない）。
4. 保存後、保存パスとファイル名を返し、未達・ブロック一覧も併記する。

## ルール / Rules

1. **上書き禁止**。同日の既存 recap には追記する。
2. **短く、action-first**。1 項目 1 行。長い説明は要約の意味がない。
3. **具体物を添える**。commit hash・URL・ファイルパス・コマンドを 1 つ程度入れると後で検証できる。
4. 箇条書きの見出し（達成/未達/ブロック）は必ず揃える。揃わない日は「なし」と書く。
5. 秘密（API キー・トークン）は **絶対に記録しない**。
6. 言語は日本語（ユーザー既定）。

## 呼び出し例 / Usage

```
@rec  今日の recap を保存して
@rec  今のセッションの未達とブロックを recap して
@rec  昨日の recap に追記して
```
